# H3 Colab 实战经验（2026-10-24）

这一轮在 Colab G4 上跑了两条跳舞路线：

- **整帧动作迁移**：分支 `colab/motion-transfer`，任务 `umall-bear-walk`。
- **换人**：分支 `colab/vae-approx-and-dance-check`，任务 `leather-jacket-swap`。

这里只记两类东西：读代码看不出来、只能踩出来的坑，以及已经验证可行的做法。每条都写了现象、原因和做法。

## 一、机器与费用

| 项目 | 实测 |
|---|---|
| G4 | RTX PRO 6000 Blackwell，显存 96 GB、内存 177 GB，约 **9 个计算单元/小时** |
| CPU 运行时 | 约 0.08 个/小时，内存 12 GB；用来做准备和校验 |
| 环境快照恢复 | 约 70 秒 |
| 首次从 Drive 加载模型 | 约 4.5 分钟；同一台机器第二次起快很多 |
| 动作迁移 19 秒（2 段，含运镜参考） | 1193 秒，约 3 个单元；每步 89～121 秒 |
| 动作迁移 19 秒（2 段，无运镜参考） | 926 秒，每步约 52 秒 |
| 换人 14.4 秒（FastH3 8 步） | 1792 秒，约 4.5 个单元；第 1 步连加载 11 分钟，之后每步约 102 秒 |
| 只跑 SAM 3.1 追踪（3 组） | 一分多钟 |

**错误经验**
- **G4 空着也在计费。** 改脚本、写提示词时让 G4 开着等，每小时约 9 个单元白白烧掉。
- **在 G4 上一边跑任务一边做 dry-run。** dry-run 里的 bootstrap 会先删再重建模型目录的软链接，正在跑的任务可能读到空目录。

**正确经验**
- **代码、提示词、dry-run 都先在 CPU 运行时做完。** G4 只用来出片。
- **下一条任务排在上一条后面。** 写一个脚本，用 `pgrep` 等前一个进程结束再开跑，GPU 不留空档。
- **最后排一个自动释放的单元格：**
  - 它先等所有名字含 `walk.sh` 的脚本结束；
  - 再执行 `drive.flush_and_unmount(); runtime.unassign()`；
  - 释放前要把需要的东西都写进 Drive：日志、缩略图、诊断图。`/content` 会随运行时一起消失。
- **重连一次约 6 分钟（≈1 个单元）。** 预计空等超过 6 分钟就直接断开。

## 二、动作迁移（Ref2VA 4 步 + H3 导演台）

### 背景不动、角色原地踏步

- **现象**：小熊应该举着手机边走边自拍，成片却是固定机位、背景不动，人在原地踏步。
- **原因**：
  - 提示词写了“`<Picture 1>` 的构图全程保持”“每个角色待在画面里自己的位置”。
  - 绿幕参考视频本身也是固定机位，没有任何运镜可学。
- **做法**：
  - 再挂一段**运镜参考**：`--camera-video`，作为 `<Video 2>`，camera 模式，去掉音轨。素材用原成片（真人边走边拍那条）。
  - 绿幕视频继续作为 `<Video 1>`，action 模式，只管动作。
  - 提示词删掉“构图不变”，改成正面描述背景在动：“镜头跟着走，步道和海边石墙从旁边掠过”。
  - `retention_analysis` 里**两路视频各写一句官方 mode 声明**：camera 模式的短语是 `the camera trajectory, framing changes and camera orientation`。
  - 再写一句 `<Video 2> appearance: not_preserved`，否掉原片里的人、夜景和灯光。
- **两路参考怎么对齐**：
  - 用两条视频的音轨做互相关，算出时间差。这次是 0.055 秒，约 1 帧，可以忽略。
  - 对齐后两路按同一时间轴切段。
- **副作用**：用真人成片当运镜参考，会把人和场景一起带进来，见下一条。

### 运镜参考里有真人，人和场景会一起串进来（2026-10-25）

- **现象**：
  - 两个二次元女孩那条（`catgirls-walk`）从第一帧起背景就是运镜参考里的夜景江边。
  - 白发女孩一开场就变成参考里穿米色毛衣的黑发女生；17 秒左右，连举手机的粉发女孩也变成了参考里穿粉色西装的男生。
  - 小熊那条（`bear6-walk`）轻一些，但后半段的垃圾桶、花坛、石墙也是参考场景里的东西，场景显得乱。
- **原因**：
  - 运镜参考是真人边走边自拍，构图和角色图几乎一样。模型分不清只该学镜头，把人和场景整套照搬了。
  - `retention_analysis` 里写的 `<Video 2> appearance: not_preserved` 压不住。
  - 角色越像真人，串得越厉害；毛绒熊和袋鼠串得最少。
- **做法**：
  - 不用真人成片当运镜参考。要镜头动，换一段画面里没有人的走路视角视频，或者不挂运镜参考、只在提示词里写镜头往前走。
  - 场景用一张不带角色的纯场景图作 `<Picture 1>`，角色用三视图，动作只参考绿幕视频（任务 `bear-plate-walk`，待验证）。

### 导演台把每段时长四舍五入成整秒

- **现象**：
  - 参考视频 452 帧，按 2 × 9.4167 秒切，合并后只有 418 帧。
  - 盖原音轨的版本在接缝之后差了 1.4 秒。
- **原因**：
  - `studio_node._segment_frame_count` 先用 `floor(秒数 + 0.5)` 把时长取整，再取最近的 17k+5 帧。
  - 所以 9.42 秒按 9 秒算，只出 209 帧，不是 226 帧；每段末尾都少 0.7 秒。
  - 接缝处并没有丢帧，是每段本身就短了。
- **做法**：
  - 按**整秒**分段，并按导演台实际出的帧数切参考视频。9 秒 + 10 秒 = 209 + 243 = 452 帧，和原视频逐帧对齐。
  - 整秒能取到的帧数是 56、73、90、124、…、209、243，有些 17k+5 取不到（比如 107、226）。
  - 单段最多 14 秒（328 帧）。15 秒会出 362 帧，但参考视频被截到 360 帧再降到 345 帧，两边对不上。
- **另一个坑**：ffprobe 报的 18.833333 秒乘 24 是 451.99999，直接截断会算成 451 帧，要四舍五入到整帧。

### 角色张嘴、像在说话

- **现象**：用户要求小熊全程保持图里的表情、不张嘴，第一版却在动嘴。
- **原因**：把参考视频的原音轨送进了模型（audio reuse）。音轨里有人声或节奏时，模型会给角色对口型。
- **做法**：
  - `--no-video-audio`，不送音轨，成片再用 ffmpeg 盖回原音轨。
  - 分段严格对齐以后，原音轨能全程对上。
  - 提示词按“状态锁写此刻是什么”来写：“His face holds the smile of `<Picture 1>`, unchanged from the first frame to the last”。
  - 提示词里不写“mouth / talk / lip-sync”这些词，点名反而会打开对应的运动先验。

### 只在某一段发生的事，只写进那一段

- 袋鼠在第 17.3 秒撞电线杆摔倒，落在第 2 段（8.7～18.8 秒）里。
- **做法**：
  - `--prompt-file` 按段数给多个，电线杆只写进第 2 段。
  - 写成“在最后两秒、`<Video 1>` 里白色人偶摔倒的那一刻撞上去”。动作参考里本来就有摔倒，提示词只需补上画面里缺的那根杆子。
- **结果**：seed 101 在 17.25 秒撞杆，17.75～18.5 秒倒在画面右下角。
- **注意**：多段时每段都按段 1 的图片编号写，脚本会给段 2 起自动顺延（尾帧占 `<Picture 1>`）。段 2 的提示词不要写“`<Picture 1>` 是第一帧”，否则模型会跳回开场构图。

### 环境版本对不上

- **导演台调用参数错位**：
  - 报错：`MiniMaxH3ReferenceToVideo.execute() got multiple values for argument 'ref_image_size'`。
  - 原因：固定的 ComfyUI bc5f880 改了参数顺序，快照里的导演台还按位置传参。
  - 做法：`colab/patch_director.py` 在运行时副本里改成按名字传参（482850e）。私有仓库也要改。
- **SageAttention 在 Blackwell 上缺失**：
  - 现象：KJNodes 的 `PathchSageAttentionKJ` 设为 auto，跑到第 245 秒报 `ModuleNotFoundError: sageattention`。
  - 原因：bootstrap 在 sm_120 上不装 PyPI 版的 SageAttention。
  - 做法：模块不存在时把这个节点设为 disabled（7284440）。
- **缺 taeh3 预览解码器**：
  - 现象：主视频输出被拒，报 `not in ['none']`。
  - 原因：`models/vae_approx` 里没有 taeh3。
  - 做法：taeh3 存进 Drive，`vae_approx` 加进 MODEL_FOLDERS。

## 三、换人（SAM 3.1 + FastH3 OmniRef + Character Swap 1.5）

### 后半段“又换回去了”：不是强度不够，是遮罩漏了头

- **现象**：前 8 秒换成了皮夹克男，后面戴毛线帽和墨镜的原舞者又回来了，帽子、墨镜、围巾和原片一模一样。
- **先排除强度问题**：
  - 画布用 `SetLatentNoiseMask`：只重画遮罩里的部分，遮罩外原样保留。
  - 如果是 LoRA 强度不够，应该是两张脸混在一起；原样出现说明那块根本不在遮罩里。
- **验证**：
  - 只跑 SAM 追踪那一小段子图，三组设置各一分钟，输出“原视频 | 原始遮罩 | 清理后遮罩”的逐秒对比图。
  - 原设置是 `detection_threshold 0.5`、`max_objects 1`、`detect_interval 1`。从 8 秒起他用手挡脸、摸帽子，遮罩碎成几块，**头部不在遮罩里**。
  - 把 SAM 描述词换成 “the man”：照样漏头。
  - `max_objects 4`：每一秒都盖住整个人。
- **原因**：只允许 1 个目标时，挡脸那几秒头被拆成另一个目标，进不了遮罩。放宽以后几个目标的遮罩取并集，正好是整个人。
- **做法**：
  - `run_dance_swap.py` 默认 `--sam-max-objects 4`（f35c263）。
  - 画面里有别的人入镜时调回 1，免得把路人也换掉。
  - 验证：2026-10-25 换成骑士三视图（`knight-swap` s301，用时 1707 秒），14 秒从头到尾都是新角色，捂脸那几秒也没变回原人。
- **教训**：
  - 我第一反应以为是“整段遮罩丢了”，SAM 检查结果并不支持。
  - 换人一条要 30 分钟，诊断只要 1 分钟。先用最便宜的子图验证，再决定改什么。
  - ComfyUI 的预览输出（SAM Track Preview）存在临时目录，重启就清空。需要留证据的遮罩要用 `save_output` 存下来。

## 五、用浏览器操作 Colab

- **改单元格不要靠点击和输入。**
  - 页面会随输出刷新而滚动。
  - 点击可能落在格子之间的“插入”按钮上，`ctrl+a` 加输入就写进了新插入的空格子。
  - 用页面自带的模型接口：`window.colab.global.notebookModel` 提供 `getCells()`、`getCell(id)`、`setText()`、`deleteCells([cell])`，可撤销。
- **往终端输入之前确认焦点。** `document.activeElement.tagName` 是 `COLAB-XTERM-TERMINAL` 时才输入。
  - 这次有一条命令被打进了排队单元格的编辑框。
  - 好在排队的单元格在排队时就把代码发给了内核，事后改编辑框不影响实际运行。
- **同一个运行时在第二个标签页里开的终端有时不刷新。** 改用单元格执行，或用 JS 读输出。
- **传文件用文件面板的上传框。** 对隐藏的 `input[type=file]` 直接上传，不要在终端里用 heredoc 贴长文本。
- **工具限制**：
  - 一次 `browser_batch` 超过约 60 秒会超时，拆成几次。
  - JS 返回的文字里有 `?`、`&`、`=` 或链接时会被拦截，返回前先过滤掉。

## 六、仓库

- **`README.md` 和 `colab/bootstrap_colab.py` 末尾各有一个多余的 `\r`。** 编辑工具会把它去掉。
  - 改这两个文件时，从 `git show HEAD:文件` 取原字节再替换。
  - 用 `git -c core.autocrlf=false add` 暂存。
- **全局 `autocrlf=true`**：工作区是 CRLF，暂存时会转回 LF。
  - 检查暂存区要看 `git show :文件`。
  - `git diff --cached` 的输出会被换行转换干扰，看起来像全是 CRLF。
- **两个功能分支都改了 README 的相邻位置**，合并第二个时要手工处理一处冲突。
